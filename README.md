# 论文研究与写作工作流
**调用名：`$paper-research-workflow`**

一个帮助组织论文研究与写作过程的 AI 技能。根据当前材料，聚焦研究问题、拆解文献逻辑、设计验证实验、诊断真实结果，并将证据组织为实验日志、论文章节和图表规划。

支持单阶段使用，也支持跨阶段推进。适用于学位论文及科研论文；附有 FTA（故障树分析）方法示例。

## 主要功能与输入输出

| 功能 | 需要提供的输入 | 主要输出 |
|---|---|---|
| 研究规划 | 研究对象、现有设想或论文草稿 | 明确的研究问题、候选机制、研究范围、验证路径和证据缺口 |
| 文献逻辑拆解 | 论文原文，或允许检索的可核验公开来源 | 背景→缺口→机制→证据→局限分析，原文位置及可借鉴的论证方式 |
| 核心机制验证 | 方法描述、数据说明、可用代码及运行环境 | 最小验证路径、输入输出定义、检查点与失败条件；实际执行后记录运行结果 |
| 实验设计 | 研究主张、任务、数据和可用资源 | 主张—实验对应表、基线与消融方案、数据划分、指标定义和公平比较要求 |
| 结果诊断 | 真实实验结果、配置、错误样例或中间输出 | 分组现象、原因假设、区分原因的最小验证实验和改进优先级 |
| 实验日志汇总 | 实际日志、运行配置、指标及产物 | 可追溯的运行记录、结果汇总、异常与失败记录、缺失项清单 |
| 论文结构与配图规划 | 论文草稿、方法说明及已有证据 | 章节组织建议、图表规划、可采用的结论强度及待补证据 |

不需要一次提供所有材料。技能按当前请求选择阶段，先交付能完成的具体结果，再列出证据缺口和最多三项优先行动。只有研究设想、没有代码或标注时，可以先完成研究规划与实验设计。

## 输入怎么准备

提供以下信息即可开始，未知项可以直接写“未确定”：

- **目标**：这次希望完成哪项任务，例如设计消融实验或诊断结果。
- **材料**：当前草稿、文献、方法说明、代码、数据说明、配置或真实结果。
- **状态**：哪些已完成，哪些只是设想，当前卡在哪里。
- **约束**：资源、时间、可否公开检索、资料保密要求、是否必须保持原文不变。

已有文件请提供最新版本。材料不足时会标记未知，不会用假设补造实验事实。

## 输出预览

根据任务选择相应交付物，通常包括：

1. **具体成果**：研究问题、文献分析表、实验设计表、诊断结果、日志或章节与图表规划。
2. **证据状态**：区分【已有证据】【待验证设想】【写作建议】，标出出处或实际运行依据。
3. **下一步**：列出关键缺口与最多三项优先行动。

例如，“设计消融实验”可以输出以下表格：

| 候选主张 | 验证方式 | 所需输入 | 指标与判断依据 | 当前证据状态 |
|---|---|---|---|---|
| 某模块有助于改善任务效果 | 对比完整方法与去除该模块的版本，保持其他设置一致 | 固定的数据划分、模块实现、评价协议 | 根据任务定义指标，同时检查整体回退 | 待验证，不预填性能提升 |

以上为输出形式示例，不代表已取得实验结果。

## 调用示例

### 检查论文进展
> 使用 $paper-research-workflow，根据我的论文草稿和实验结果，检查证据缺口并完成当前最需要推进的任务。

### 从研究设想开始
> 使用 $paper-research-workflow。我目前只有研究设想，没有代码和标注。请聚焦研究问题，并给出最小验证方案和主张—实验对应表。

### 设计消融实验
> 使用 $paper-research-workflow，根据我的方法与数据说明，设计消融实验，明确控制变量、指标和数据划分，不把设想写成已证实成果。

### 分析真实结果
> 使用 $paper-research-workflow，根据这些真实结果、配置和错误样例，分析低表现原因，并提出能区分原因的最小验证实验。

### 组织论文与配图
> 使用 $paper-research-workflow，根据现有方法和证据，规划论文章节与图表，指出哪些结论需要降低表述强度或补实验。

## 证据与保密规则

- 不虚构文献、数据、运行记录或性能提升；未运行时不声称跑通。
- 保留失败记录，防止数据泄漏和选择性报告；结论强度不得超出证据。
- 不默认上传论文、数据、代码、日志或原始资料到外部服务；上传须有具体授权。
- 不自动投稿、发布、发消息、创建远程仓库或安装依赖。
- 用户要求原文不变时，仅组织、排版或标注；严格 Word 排版交由专用技能。
- 精确算法、矩阵和数据图使用代码或矢量工具绘制。

实际代码执行、公开检索和文件生成取决于使用环境的工具与授权。该技能提供工作流程，不自带训练模型、数据集或自动建树程序。
