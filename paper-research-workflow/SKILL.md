# 论文研究与写作工作流

## 基本规则
- 以用户当前请求选择工作范围；单阶段任务直接完成，不强制走全流程。
- 区分【已有证据】【待验证设想】【写作建议】，不得把候选贡献写成已证实成果。
- 不虚构文献、出处、数据、运行记录或性能提升；材料不足时标记未知，并完成可独立进行的部分。
- 不将论文、数据、代码、日志或原始资料上传到外部服务。仅在用户明确授权了具体材料与目的后上传。公开信息检索不要携带未公开细节；禁止上传要求生效时仅用已提供材料。
- 不自动发布、投稿、发消息、创建远程仓库或安装依赖。遵循用户授权范围及环境要求。
- 保留原始实验结果和失败记录；不以提高数值为理由选择性删样本、变更测试集或反复调测试集。
- 用户要求内容不变时仅组织、排版或标注，避免改写。Word严格排版交给专用技能。

## 入口与阶段判断
1. 阅读用户实际提供的文件和当前材料，列出可用证据及缺口。历史上下文仅作为定位线索，不代替读取最新材料。
2. 识别目标：研究规划、文献拆解、实验设计、结果诊断、日志汇总、论文组织或图示规划。
3. 判断最早阻塞环节：问题不清→规划；机制未运行→最小验证；主张无实验→实验设计；结果有异常→诊断；证据齐全→写作。
4. 仅询问会阻塞当前任务的关键问题。其他信息以明确标记的假设推进；不得用假设填充实验事实。
5. 按需读取 [阶段流程](references/stages.md)，使用 [工作模板](assets/work-templates.md)。FTA任务再读取 [FTA示例](references/fta-example.md)。

## 阶段路由
| 模块 | 最低输入 | 完成条件 |
|---|---|---|
| 研究规划 | 研究对象、现有思路或草稿 | 问题、机制、验证方式可对应，范围明确 |
| 文献拆解 | 原文或可核验公开来源 | 每项分析有原文位置，作者主张与自己的推断分开 |
| 核心验证 | 方法描述、数据说明、可用代码 | 最小路径及检查点明确；未运行不得声称跑通 |
| 实验设计 | 研究主张、任务、数据和资源 | 主张都有实验，公平性与评价口径明确 |
| 结果诊断 | 真实结果、配置、错误样例 | 分组现象、原因假设、验证动作分开 |
| 记录汇总 | 日志、配置、实际输出 | 每条结论可追溯到运行，缺失项可见 |
| 结构与图示 | 草稿、方法及证据 | 章节与图表服务同一问题，贡献强度不超证据 |

## 交付与质量检查
- 先交付当前任务的具体结果，再列证据缺口及最多三项优先行动；不只提出计划。
- 多阶段任务维护项目状态：材料版本、当前问题、候选主张、运行索引、证据状态、下一步。
- 小任务在对话中交付；用户要求文件或需要复用时按环境的文件持久化规则保存。原始资料保密要求优先。
- 检查每项结论是否有出处或运行依据，是否标记不确定性，比较是否公平，失败结果是否保留。
- 检查引言问题→方法机制→实验验证→讨论边界是否闭合；不闭合处先降级表述或补验证。
- 绘制算法、矩阵和数据图时使用精确的代码或矢量工具，不用生成式图片代替科学信息。
